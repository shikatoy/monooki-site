# 一度きりのタスク：3社の現行ラインアップと寸法を公式で取り切る

あなたは物置比較サイト「物置どれがいい？」のデータ保守担当です。

いま `PRODUCTS` には **18機種**しか載っていません。しかも**寸法が取り切れていません。**
例：タクボ Mr.ストックマン ダンディは、掲載データでは間口1832mmからになっていますが、
公式のサイズバリエーションでは **間口1316mm から** 5815mm まであります。**掲載が間違っています。**

**目的は2つです。**

1. 対象メーカーの**現行機種をすべて**拾って `PRODUCTS` の抜けを埋める
2. 各機種の**全型番の外形寸法（間口・奥行・高さ）を取り切る**

対象メーカーは、この指示の最後に書かれた1社だけです。**他社は今回触りません。**

## なぜ寸法が要るのか（作業の判断基準になるので必ず読むこと）

これから書く記事は、**「自分の置き場所に入るものが、3社にそれぞれあるか」**を比べるものです。
物置を買う人が最初に気にするのは寸法で、**小型・中型・大型といった区分ではありません。**
（区分はサイトの管理都合で付けているだけです。読者には関係ありません）

**だから、寸法が虫食いのままだと記事が書けません。**
「タクボは幅1.3mから作っている」と書けるかどうかが、全型番を取れているかで決まります。
**機種を増やすことより、寸法を取り切ることのほうが大事です。**

## 触ってよい範囲

- `index.html` の **`PRODUCTS` 配列** と **`UPDATE_LOG` 配列**
- 新規作成する `~/Documents/ObsidianLocal/参照_3社の公式仕様.md`（後述）

**それ以外は1文字も変更しないこと。**
`ARTICLES` 配列・ナビ・セクション構造・スクリプト・CSS・他のファイルには触れない。
**git コマンドは実行しないこと。**

## 手順

### 1. いま何が載っているかを把握する
`index.html` の `PRODUCTS` を読み、対象メーカーの `id` / `name` / いま入っている型番数を書き出す。

### 2. 公式で現行機種を全部拾う
- イナバ物置 https://www.inaba-ss.co.jp/monooki/lineup/
- ヨド物置 https://www.yodomonooki.jp/products/lumberroom/
- タクボ物置 https://www.e-ty.co.jp/seihin/

**物置・収納庫だけでなく、ガレージ・バイク保管庫・大型倉庫・断熱物置も対象です。**
一覧の見た目で判断せず、**個別ページを開いて分類表記と型番を確かめる。**

### 3. 全型番の寸法を取り切る（ここが今回の本体）

**公式サイトのシリーズ紹介ページには寸法表が無いことが多い。**画像やPDFの中にあります。
次を順に開いてください。**「ページに書いていなかった」で終わらせないこと。**

- **サイズバリエーション／寸法一覧のページ**（例 `.../size.html`、`/seihin/<型番>/`）
- **電子カタログ・WEBカタログ**
- **データダウンロード**（寸法表PDF・外形図面PDF）
- **各型番の個別ページ**

取れた型番は `sizes` に `{ code, w, d, h }` で入れる。
- **全型番を取り切れたときだけ `sizesComplete:true`**
- 一部しか取れないなら `sizesComplete:false` にして、取れたぶんだけ入れる
- **高さが取れない型番は、間口・奥行だけで入れない。**取れるまで探すか、その型番は入れない
- 一般型／多雪型（積雪地型・豪雪型）で型番が分かれている場合は、**両方入れる**

### 4. 抜けている機種を `PRODUCTS` に足す

**既存エントリと同じ形をそのまま真似ること。**新しい書き方を発明しない。
`t-pe`（ペインタ）と `y-ese`（エスモ）が見本になります。

必須：`id` / `maker` / `name` / `cat` / `steel` / `door` / `found` / `look` /
`doorSpec` / `tags` / `features`（3つ）/ `base`（1文）/ `link` / `added` / `sizes`

- `id` … `i-` `y-` `t-` ＋ 型番の記号を小文字で（例 `y-lmd`）
- `cat` … 既存で使われている値から選ぶ。**新しい `cat` を勝手に作らない**
- `elev` … 開口寸法が公式で拾えたときだけ書く。拾えないなら書かない
- `look` の `seen:true` は**ボスが実物を見た機種だけ**に付くもの。
  **今回追加するものは必ず `seen:false`**
- `base` と `features` は公式の記載にもとづくこと。**使用感・体感は書かない**
  （ボスは下請けで施工のみ。使ってはいない）
- 色違い・コラボは別機種として載せ、`variant:{ of:'y-lmd', kind:'色違い' }` を必ず付ける

### 5. 仕様の数字を別ファイルに控える

記事で3社を比べるのに使います。`~/Documents/ObsidianLocal/参照_3社の公式仕様.md` に、
**対象メーカーの分だけ追記**してください（無ければ新規作成）。

機種ごとに、公式に書いてあるものだけを、出典URL付きで。**推測で埋めない。**

- 棚板：標準装備か／枚数／高さ調節のピッチ（例：タクボND=50mm間隔、ヨドエルモ=100mmピッチ 標準11段階）
- 床：有無／床耐荷重の数値（例：タクボND=6000N/㎡）
- 雪：一般型と多雪型の耐積雪の数値、雪下ろしの目安（例：タクボND=一般1200N/㎡・多雪3000N/㎡、20cm／50cm）
- 屋根：結露対策の屋根が選べるか（例：タクボ=結露減少屋根）
- 色：本体色・扉色の数と色名
- 扉：開き方、開き方向を現地で変えられるか、開口寸法
- 保証：年数の記載があるか（**無ければ「記載なし」と書く**）

**公式に無いものは「記載なし」と書くこと。**販売店・ブログの数値は使わない。

### 6. 公式から消えている既存機種

**消さないでください。**報告文に「公式で見つからなかった」と書くだけにする。判断はボスがします。

### 7. `UPDATE_LOG` に1件足す

先頭に追加。`body` は**300〜600字**で、次の4つを必ず入れること。

1. 何が変わったのか
2. 具体的に何を足したか（シリーズ名と、寸法を取り切った機種）
3. どこを見れば分かるのか
4. 読む人にとって何が変わるのか（診断や比較でどう効くか）

**箇条書きにしない。文章で書く。**
禁止表現：「〜がおすすめです」「〜は重要です」「一般的には〜」「〜と言われています」

## 最後に、報告文を出す

1. **足した機種**（`id` と `name`、何件か）
2. **寸法を取り切れた機種／取り切れなかった機種**（後者は、どこまで探したかも書く）
3. **見送った機種と、その理由**（必ず列挙する）
4. **公式で見つからなかった既存機種**（あれば）
5. **掲載が間違っていた箇所**（今回のタクボNDのような例）
